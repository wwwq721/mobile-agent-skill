# 迁移.md · screen

**根本目的**：原话见 `SKILL.md` 开头（只存一份）。

用途：换机、重装、或隔很久回来接着改之前读这一页。**只写"动手时要注意什么"，不重复已有内容**——
现行做法在 `SKILL.md`（通用）与 `scenarios/desktop.md`（桌面），实验依据在 `references/实测记录.md`。

## 一、首次部署要注意（新机第一次装本技能）

1. **先装无障碍**：设置 → 无障碍 → Minis。服务名 `com.openminis.app/.accessibility.MinisAccessibilityService`。
   **也可以设成音量键快捷键**：设置 → 无障碍 → 无障碍快捷方式（有的系统叫"快捷方式/无障碍按钮"），把目标选成 Minis，
   之后**长按音量键**即可开关。入口名称、是否支持、长按上下键哪一个是开机还是关机，**各机型/系统版本不同，用的时候现查本机设置**，别照抄。
   `android-a11y-cli service status` 看 `running:true` 只是必要条件，**`state:ON` 也可能 `permissionHeld:false`**，那时只剩状态条节点、点按全废。
2. **别信别人机器上的数值**：`device.json` 删掉，先 `scr doctor --save` 用截图元数据量屏幕与缩放，再用 `scr grid` 逐页核对格子中心（偏差 >30px 就重测）。
3. **首次跑回归**：`python3 regress.py`，14 项必须全绿；红了先修环境（无障碍/截图/前台），不要改用例迁就环境。
4. **桌面整理类任务先存档**：`scr grid --json …`，否则误合成文件夹后无法按坐标还原。
5. **装软链**：`ln -sf /var/minis/skills/screen/scr /usr/local/bin/scr`（脚本里写死了 `/var/minis/skills/screen/` 路径，挪目录要同步改）。
6. **依赖**：`python3`、`android-a11y-cli`（无障碍通道）、`android-shizuku-cli`（本机被 Agent 级禁用，不用它）。没有 `device.json` 时首跑会自己量屏幕并落盘。
7. **改完升 `version`**：SKILL.md front-matter 的 `version` 每次改行为都要递增，方便回看哪版做了什么。
8. **别用设置 App 当被试**：某些页面会把前台切到 `com.miui.securitycenter` 造成假失败；测试统一用 **B 站（`tv.danmaku.bili`）**。

## 二、换机时（按这个顺序，别跳）

1. 删 `device.json` → `scr doctor --save`；
2. `scr grid` 核对列/行/格子中心，把结果回填（工具会写盘，人只核对）；
3. `regress.py` 全绿；
4. 只有到这一步，才去看 `references/实测记录.md` 第 1、7 节"哪些限制可能随机型变"。

## 三、改代码后必须做的

**失败先取证，再改参数**：`python3 regress.py`（整跑）或 `python3 regress.py "<单项名>"`，
失败项自带可读原因；手势这类中途态用 `learn_timing.py` 或直接抓帧。


- 改 `scr` 任何子命令 → 跑 `python3 regress.py`（≤900s），全绿才算完；
- 输出文案变了 → 同步 `SKILL.md`「怎么读输出」与报错表（那里是照抄真实输出的，两处都是权威）；
- 参数默认值变了 → **别改文档**，文档一律指向 `scr <cmd> --help`（只在场景文档留一行示例）；
- 新增/删除子命令 → 更新 `SKILL.md` 速查表 + 路由表。

## 四、改之前先看限制

限制清单只在 `scenarios/desktop.md` 第二节（能力矩阵），实验依据在 `references/实测记录.md` 第 2、3、5、6 节。
这里不重复——同一事实只留一处权威。
