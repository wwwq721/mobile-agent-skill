# 场景：桌面（读取 / 整理 / 拖图标）

**根本目的（用户原话）**：「把桌面程序移动成这个样子，在图片中没有的程序就按这个规律分类就行」——用户要把散在 2~5 页的应用归到第 1 页的文件夹里，最后只剩两页。

只在**要读或改桌面布局**时读这份；点按钮、填表、开 App 请看 `../SKILL.md`。

## 一、读桌面：`grid`

```bash
scr grid                  # 只读**当前页**（默认，1~2s；改哪页看哪页）
scr grid --pages 3        # 读第 1..3 页（盘点用）
scr grid --all            # 读全部页（换机/大扫除时才用，约 10s）
scr grid --json out.json  # 把读到的写进文件（改布局前存档）
```

**别为了一页的改动去翻全盘**：翻页会打断图标暴露（要重新预热）、还会改变"当前页"，读得越慢越容易出错。

**只是找图标/点图标 → 用 `scr look`，不用 `grid`**（`look` 一次 dump 就给名字+坐标）；
`grid` 多做的只有三件事：把坐标换成 `r3c2` 这种格位、列出空位、把 2×2 小部件单列。
所以：找图标/点图标 = `look`；要知道"哪格空着、图标在第几行第几列" = `grid`（单页一次 dump，1~2s）。

口径（实测，别混）：

- **两套坐标**：普通桌面那套在 `device.json`（换机重测）；编辑模式那套数值见 `../references/实测记录.md` 第 1 节。`grid` 给的是普通桌面那套，混用会点到邻格。
- 桌面平时**不暴露图标节点**：`grid` 先"预热"（短暂进出编辑模式）才读得到，读出的是普通桌面坐标。
- 2×2 及以上小部件单列「小部件」，不占格位；文件夹在无障碍里没有文字，显示 `(文件夹)`。
- 扫完会复位到起始页，**页码会变，换页前先确认**。
- 网格数值存在 `device.json`，换机后 `scr doctor --save` 重测。

## 二、拖图标：现行做法（2026-11-26 实测）

**一条命令就够了**（原生 `gesture drag`，无需手工构造路径）：

```bash
scr drag 188 1711 790 2037                      # 同页：起点 → 终点（设备像素）
scr drag 1091 2037 1210 2037 --hold 1500        # 跨页：拖到屏幕右边缘并悬停
scr drag-into "某个 App" r6c4                    # 目标给格子，自动找图标、按格心落
```

底层是 `android-a11y-cli gesture drag`（1.16-beta.8 起，语义见 `../迁移.md`「版本相关」）。
`scr drag` 的对应参数是 `--pick`（按住）/ `--ms`（移动段）/ `--hold`（落点或边缘悬停）；**示例数值是传入值，默认以 `--help` 为准**。

实测过的结果：

| 动作 | 结果 | 证据 |
|---|---|---|
| 同页搬一格 | ✅ | 某个 App 5-1 → 6-3、5-1 → 6-4、6-4 → 5-1，每次 `grid` 复读确认 |
| 跨一页 | ✅ | 拖到右边缘悬停：第 1 页 → 第 2 页，图标落在第 2 页 6-4 |
| 跨两页 | ✅ | 左边缘悬停：第 3 页 → 第 1 页，图标落在第 1 页 5-1 |
| 拖进文件夹合并 | ⚠️ 要按顺序 | 落点语义是"插入位"：压中文件夹所在格 = 把图标插到它**之前**，文件夹被挤后一格（两次实测都是这样）。`drag-into` 已做规范化：源在目标之前时，先搬到目标之后的空格，再按"源在后"合并；落完**打开文件夹核对成员名**才算成功 |
| 从文件夹拖出 | ✅ 2026-11-26 首次成功 | 在文件夹视图里按住图标拖到屏幕上方（y≈200）松手：文件夹关闭、图标留在桌面 1-4（`grid` 复读确认） |

跨页要点：**悬停时长决定翻几页**（具体秒数见 `../references/实测记录.md` 第 5 节），拖完必须复读页码与落点；`--hold` 太小不翻页、太大可能多翻。

## 三、已知坑（都会真的弄乱桌面）

- 误合成：第 3 页曾从 12 个图标变成 3 图标 + 4 文件夹，就是这么来的。
- 从文件夹拖出做不到 → 进错文件夹的图标只能人工拖出。
- 批量搬运**未验证**：新通道刚跑通单步，整批还没试；落点仍可能压到图标。
