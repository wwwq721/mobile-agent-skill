# 迁移.md · x-browser（`bw`）

> 给"下一个接手这个技能的人"：**第一次装到一台新手机上**要注意什么，**以后改代码**要注意什么。
> 命令与判据看 [SKILL.md](SKILL.md)，实现细节看 [reference.md](reference.md)；这里只写"换机就废"和"改错会出事故"的部分。
> 本机（2026-11-21/22/23 实测）：Android 10 / MIUI / 1280×2772 / X 浏览器 `com.mmbox.xbrowser` / Sogou 输入法。

## 一、第一次部署（新机落地）

顺序不能反：**先过权限关 → 再装盘 → 再逐项验收**。跳过前面，所有"打开失败"都会被误判成"页面空白"。

| 步 | 做什么 | 怎么判成功 | 踩过的坑 |
|---|---|---|---|
| 1 | 放行无障碍（**用户手动**：设置 → 无障碍 → Minis 打开） | `android-a11y-cli service status` 里 `running:true`，且 `ui dump` 能读到浏览器节点 | `state:ON` 也可能配 `permissionHeld:false`，此时只剩状态栏节点、点按全废；**以 dump 能否读到节点为准**，别看字段 |
| 2 | 装软链 + 四个外部依赖 | `ln -sf /var/minis/skills/x-browser/bw /usr/local/bin/bw`；`bw -h` 有输出；再各自自检一条：`bw fast https://example.com`（要 `minis-browser-use`）、`bw shot`（要 `scr`，来自 screen 技能）、`bw state`（要 `android-a11y-cli`）、`bw go`（要 `android-open`） | 四个依赖都不在 `bw -h` 里：缺 `scr` 只有 `bw shot` 报错，缺 `minis-browser-use` 只有 `bw fast` 报错——验收清单里不逐个跑就会漏 |
| 3 | 确认"能把自己切回前台"这条路（`bring_minis_front()`：Recents → 点 Minis 卡片） | `bw go <url>` 的首行含 `intent`，且耗时 <1.5s | Recents 里卡片标签形如 `Minis,未加锁`；卡片坐标换机要重测。用户不想被打断时 `BW_NO_FRONT=1`（退回"新建标签+地址栏"，慢约 0.5–4s）。原理见 §4.4 |
| 4 | 体检 | `bw state` 打出《标题》+ 块数/字数 | 报"读不到浏览器界面 / 只看到状态栏节点"= 熄屏或没在前台，**不是**技能坏了 |
| 5 | 逐项验收（判定字段，不抄数值） | 见 §五：每条都给"命令 → 期望首行/退出码"。`close` 要安全地验：先 `bw go --new <公开页>` 自己开一张，再 `bw close` | 拿旧机数值当期望值 → 把"慢"判成"坏"；**别拿用户正开着的标签试 close** |
| 6 | 留基线 | 部署完先 `git add` 再改；`git log` 记下这次提交号；回退基线见 §九 | 没提交就改，改坏了回不去 |

**新机第一件事是重测几何，不是改代码**。屏幕、地址栏、底栏、卡片边界、键盘回车键都会变（§三 的表就是从 1080×2400 换到 1280×2772 得来的）。

- `_measure()` **只在第一次成功 dump 时测一次**（要求那一帧里浏览器节点 ≥5 个），之后冻结。首帧若是状态栏/Min.is 的屏，量出来的 W/H/TOP/BOTTOM 是错的且不会自愈——症状是"正文被裁一半"或"点哪都不对"。
- 取样命令：`android-a11y-cli ui dump` → 根节点 bounds 最大值＝屏幕；包内可点节点里 top 最靠下者（>0.85H）＝底栏上沿；顶部宽条（宽>0.55W、高 90–190、top<0.25H）的 bottom＝地址栏下沿。
- **常量只影响"测量失败时"的兜底**，改常量不等于改判据；错位就改判据或加兜底。
- 键盘「前往/开始」的 y：`bw shot` 截图量取（本机 Sogou 在 1180,2586），代码先试 `H-186` 再退 `H-100`，两条都不灵就按截图加一档。

## 二、后续修改注意事项

按"你要动哪块"查，每格都写清**必须连带做什么**。展开的证据在 §四 对应小节。

| 要动 | 必须连带 | 否则会怎样 |
|---|---|---|
| 屏幕/几何（`_measure`、`addr_bar`、`tab_rows`） | 只用实测值或比例，**不许写死坐标**；注意 `_measure` 用 `top<0.25H` 找地址栏、`addr_bar()` 用 `top<0.6H` + 左右留白（>0.02W、<0.98W），两套阈值不要合并；改完跑 `bw state` + `bw tabs verify` | 换机即废；本机曾因 `W,H=1080,2400` 丢掉正文 2255–2574 段 |
| `go` 的开页逻辑（含 `via_bar`） | 同时检查四处：**记账**、**失败清理**（`_bar_cleanup`）、**失败语义**（exit 3）、**复用判据**（与 `close` 同一套 `_title_match` 容错）；连 `#`/`;` 分支也要先开新标签 | 曾经"没跳走"报成成功，还把用户的页记成我开的；带锚点的 URL 会顶掉用户当前页 |
| 记账（`shared/bw/session.json`，**跨会话共用**） | 一条标签一条记录；只在**确认落地**时写。写入者共五处：`note_tab`（新开/未知）、`rename_active`（地址栏复用＝同一标签，就地改名）、`retitle_active`（`tap` 后页面变了，追加）、`switch_tab`（切标签）、`prune_state`（清理）。`session_titles()` 会把 `last` 也算一条 → **记录数≠标签数**。所有读改写都在 `state_lock()` 里（`@with_lock`） | 曾把 15 条记录删光而标签还开着；复用不记账会让卡片变成"关不掉的孤儿"，3 次后被丢弃 |
| `close` | 只为"没用"而关，不为整齐而关；守住五条：只关自己开的、关一张的判据是"这个标题少一张"、数量护栏 `after = before - closed`、面板数到 0 张判 `noview` 不许动账、**满屏（`before>=10`）改用标题逐张核对**；`--keep 片段` 命中的不关、记账保留 | 2026-11-19 曾因"全屏卡片数少一张"连坐关掉用户 5 张卡 |
| 面板（`open_tabview`/`_cards`） | 进面板前先收键盘；进面板后**再确认一次** `in_tabview()`；卡片判据三档：① 标题行同一 y 带靠右 × 小图标（`left>0.80W`、宽<0.15W、高<0.08H）→ ② 带 × 的行里取出现最多的 `(left,right)`，并列取 left 更大 → ③ 按 top 间距 ≤240 截断 | 少任一轮都会数错：只按几何会把网页正文当卡片，不收敛会把正文里挨着图标的行算进来 |
| 拟人（`human`） | 点击只能真实触摸；`tap xy` 两次不中报失败，**不许退回注入式 `tap node`**；新开页必须先 `open_new_tab()` 再打字 | 注入点击没有触摸事件，页面能识别；直接在地址栏打字会顶掉用户当前页 |
| 错误文案 | 报事实（前台是谁、看到几个节点），不猜病因；给一条可执行下一步 | 把熄屏/前台不对/真空壳混成"页面被裁" |
| 文档 | 改行为必须同步 SKILL.md 的命令行与默认值、reference.md 的机制描述、本页的约束；**三处不许互相矛盾** | 2026-11-21 发现 SKILL.md 还写着"close 回桌面"、reference.md 还写着旧机 `H-100` |

**改记账/`go` 不用真机也能先验**（桩测，2026-11-23 用它抓出 `prune` 丢账）：

```python
import types, json, tempfile
src = open('/var/minis/skills/x-browser/bw', encoding='utf-8').read().replace('if __name__ == "__main__":', 'if False:')
m = types.ModuleType('bw'); exec(compile(src, 'bw', 'exec'), m.__dict__)
m.STATE = tempfile.mktemp(); m._OLD_STATE = m.STATE + '.none'
json.dump({"tabs": [{"title": "A", "ts": 0}, {"title": "B", "ts": 0}], "active": 1, "last": "B"}, open(m.STATE, 'w'))
m.prune_state(["A"], ["B"], [], inspected=True)          # A 关掉、B 还在 → B 必须留、tries=1
print(json.load(open(m.STATE))["tabs"])
```

再跑 `python3 -m py_compile bw`。真机只留最后一步确认。

## 四、本机硬约束（不是 bug，改不掉；改代码前先对一遍）

### 4.1 Minis 在后台时，系统拦后台启动
- 现象：`android-open` 可能返回 `Opened:` 而屏不动，或跳到 `com.miui.securitycenter`；表现是 `✘ 没打开：前台是 com.miui.home`。
- 现场话术：**"点一下 X 浏览器图标，再说一次"**；不要反复重试，也不要建议 `bw open`（命令不存在）。
- **别把"授权状态"当事实写进文档**：这是会变的环境状态，写死会让下一个 agent 照着它去翻设置。只记"需要什么、怎么验、被拦时什么表现"。
- 本机实测：**没有**「后台弹出界面/允许后台启动」这类能给 Minis 开的开关（2026-11-22 核实），别建议用户去开。
- 能自己做的那一步，原理与代价见 §4.4（`bring_minis_front` / `BW_NO_FRONT`）。

### 4.2 熄屏读不到界面
熄屏后 `ui info` 只报 `com.android.systemui`（windowCount=1），`dump` 只剩状态栏节点；无法远程点亮。
已明确报：`✘ 没打开：读不到浏览器界面 / 只看到状态栏节点——屏幕可能锁着/熄了`。

### 4.3 地址栏未聚焦时读不到 URL
"到底跳没跳"没有可靠字段，只能看正文或地址栏里已有的域名。所以落地判据**不用**签名变化（点开地址栏本身就会变，曾出现 460ms 假成功），用 §4.7 那三条。

### 4.4 VIEW intent 只在 Minis 在前台时能送达（后台启动被系统 cancel）
- **真因不是"浏览器在前台"**：浏览器在前台 ⇒ Minis 在后台 ⇒ Android 10 直接 cancel 这次 `startActivity`，且 `startActivity()` 不抛异常、`android-open` 照样回 `Opened:`。
  2026-11-22 矩阵实测：同一条 `intent:...VIEW;package=com.mmbox.xbrowser` 在 Minis 前台 **21ms 落地**并新开一张卡；把浏览器切到前台再发，页面一字节不动；**连公认能用的 `MAIN/LAUNCHER` 在 Minis 后台时也不动**。换 data/package/flags 都没用。
- 代码按前台分三档（`_go_impl`）：
  1. 新开页 + 浏览器在前台 → **先 `bring_minis_front()`**（Recents → 点 Minis 卡片）再发 intent，实测 457ms；切不回来或 `BW_NO_FRONT=1` → "新建标签 → 地址栏"（541ms，不闪屏）。
  2. 复用我的页 → 走地址栏（intent 会开新标签），约 4s；成功后**就地改名**（`rename_active`）。
  3. Minis 已在前台 → 直接 intent，0.5–0.7s。
- 没落地时：页面没变且地址栏无目标域名 → `exit 3`、**不记账**；地址栏失败要 `_bar_cleanup()`（见 §4.7）。
- 带 `#`/`;` 的 URL 走"新建标签 → 地址栏"；地址栏两次都没成时才会退回 intent，**那时锚点会丢**，输出里会明说，别把这次当成"开对了"。

### 4.5 面板一屏只放得下十来张卡
- `verify` 与 `close` 的 `before/after` 只覆盖当前一屏。2026-11-22 实测：13 个标签时面板只显示 11 张。
- 所以 `before >= 10` 时 `close` 不再用数量判成功，改**按标题逐张核对**，并在输出里说"面板满屏，卡片数不可靠"。
- 关的是当前标签时，浏览器会自动补一张空白页（11→11）；不算异常，输出里也会说明。

### 4.6 `open_tabview` 会假成功
出现过"报进了面板，但下一帧已被带回网页"：`before` 数成 0 → 判成"我的标签都不在了"→ 连删 15 条记录，而标签其实还开着。
防护两道：进面板后再确认一次 `in_tabview()`，否则 `noview`；`prune_state(inspected=False)` 时账本一个字不动。

### 4.7 地址栏提交要试三条路，且"落地"不能只看标题
- 三条路：键盘「开始」`H-186` → 地址栏右侧箭头（`0.9375W`, 地址栏中心 y）→ 键盘 `H-100`（旧机）。本机顶部地址栏打完字键盘有时自己收起，只剩箭头可点。
- **落地判据＝键盘收起 + 地址栏不再显示我刚打的字**。反例：`example.com` 与 `example.org` 标题都叫 `Example Domain`、正文 900 字一字不差，"标题变了"和"内容变了"都会判失败。
- 失败的地址栏输入会留下**联想浮层**（键盘已收，列表里有一行 `搜索:`）：不收拾，下次 `go` 会把浮层里的字当成"地址栏已是目标域名"→ 假成功。所以失败一律 `_bar_cleanup()`（按一次 back），域名判据额外要求 `not ime_up` + 正文 ≥80 字。

### 4.8 面板刚打开时数不到卡片（`verify` 也会）
- 实测 `open_tabview()` 成功、`in_tabview()` 也真，但 `_cards()` 在动画中返回 0 张 → 旧逻辑据此判"我的标签都不在了"，把记录当成已关。
- 现在：等 2.5s 仍为 0 → 退面板重开一次 → 再等 2.5s 仍为 0 → `noview`，账本一个字不动。`bw tabs verify` 同样要等（刚 `close` 完立刻 verify 会把 1 张报成 0 张）。
- 另有计数上限：**最后一张标签没有 ×**（浏览器不允许关最后一个），不在"带 × 的卡"里。只剩它时 `_cards()` 为 0，`close` 判 `noview`（安全），`verify` 会补一句说明。

### 4.9 `bw find` 慢且脆（17–22s）
原因链：必应移动版结果块延迟渲染（落地只有 132 字搜索头 + 一张广告卡，6–8s 后才出条目），intent 有时还停在原页。
兜底：搜索页标题不匹配 → 走地址栏重开；解析不到 → 下滑最多 2 屏再解析。
要快就走 `bw go "https://cn.bing.com/search?q=..."` → `bw read` → `bw tap`，能省一半时间。

## 五、验收基线（2026-11-21/22/23，本机）

按"命令 → 期望"跑，数值可不同，**首行关键字与退出码必须对**。

| 命令 | 期望 | 本机实测 |
|---|---|---|
| `bw state` | 首行 `《标题》 … 前台=com.mmbox.xbrowser` | 0.14–0.35s |
| `bw read` | `《…》 N 块 / M 字`，正文非空 | 0.13–0.18s |
| `bw go <公开页>` | `✔ 打开 · …`，exit 0，标题是目标站 | 新开 457–700ms / 复用 4.0–4.1s |
| `bw tap <链接>` | `✔ tap … 页面变了`（没变化是 `…` + exit 3） | 0.8s |
| `bw tabs` | 列出记账；当前项带 `←` | 0ms（不碰屏幕） |
| `bw tabs verify` | `剩 N 个（面板共 M 张卡，记账 K 条）`；账里有、面板找不到的会另起一行说明；剩 0 时 exit 0 | 0.2–0.8s |
| `bw tabs panel` | `当前页《…》；面板 N 张卡：` + 逐条标题（只读诊断，不判成功） | 0.6s |
| `bw close` | `✔ 关掉并核实 K 个`，`after = before - K`（满屏时只说按标题核对） | 2.2–2.8s |
| `bw human on` + `bw go` | `· 拟人` 前缀，走地址栏，且**新开标签**不顶用户页 | 0.55–0.6s（本机进入地址栏快路径） |
| `bw fast <公开页>` | `✔ 内置取正文 · 打开 …ms · 读完 …ms` | 打开 1.8s / 3.4s / 30.7s（example.org / example.com / iana.org），读完 8–10ms |
| `bw find <词>` | `✔ …` | 17–22s（见 §4.9），能不用就不用 |

## 六、未验证 / 已知短板

1. **`dismiss_dialog` 仍未验证**：它按文字点（取消/关闭/以后再说/不允许），不依赖坐标；但这台机器上找不到**可确定性复现**的弹窗入口（下载提示/权限框都由内容触发），所以只验了"没弹窗时不乱点"。要在真机上验，得先准备一个必然弹下载框的链接。
2. `bw` **没有** `scroll to-text` 这个命令（`android-a11y-cli scroll to-text` 是另一层工具，`bw` 没用它）；滚动只有 `bw read -n`（已测：下滑 1 屏 778ms）。
3. 拟人输入已在 2026-11-23 真机验证：必应搜索框写入"测试输入abc"后**回读一致**；`type` 现在自带回读校验（框里的值和写入值不符就 exit 3），`--submit` 走"按钮 Search"成功（1580ms、页面变了）。百度页那次"没有可写的输入框"仍未复现，原因未定位。
4. `key back`/`key fwd` 已测（有历史时）：back 486ms、fwd 535ms，都"页面变了"。无历史的页面上两者都会报"页面没动"，属正常。
5. **面板一屏 = 11 张**（2026-11-23 实测：≥12 个标签时仍只显示 11 张）。所以 `close` 的"满屏"阈值取 `>=10` 是保守值，可用；按行高精算没有必要。
6. 拟人输入是 `ACTION_SET_TEXT` 逐段重写，**没有 keydown**——靠 `isTrusted`/`keydown` 判人的站点仍能识别。
7. 页面里的内联 SVG data URI 曾被当正文打出来（必应一次 7497 字全是 svg 路径）；已按 `svg+xml` / `%3Csvg` / 长 data URI 过滤。

## 七、判断"这张要不要留给用户"

`close` 只为"没用"而关，不为整齐而关。判断顺序：

1. **你还要用**（登录页、填了一半的表、接着要点的页）→ 别让它进名单。
2. **拿不准** → 不关。少关一张的代价（用户自己点一下 ×）远小于多关一张（登录态/填好的东西没了）。
3. **要收尾但留一两张** → `bw close --keep <标题片段>`：命中的不关，记账也保留，下次还能接着管。
4. `bw tabs close <片段>` 是**显式点名**：它不看 `--keep`，会直接关命中那张——想留就别用它点名。

## 八、其余已修事项（§二/§三/§四 没覆盖的；过程细节查 `git log`）

| 现象 | 修法 | 别改回去的理由 |
|---|---|---|
| 一次 `bw go` 挂死，shell 900s 超时、日志 0 字节 | `_open()` 统一 15s 超时 | 无超时会把整条命令链拖死，看不出卡在哪 |
| `bw state \| head` 抛 `BrokenPipeError` 堆栈 | `__main__` 兜住 | 管道截断是正常用法，不该打堆栈 |
| `go` 一次回退要 19s | `via_intent(wait_ms=3500)`、`_bar_retry` 2→1 次 | 回退那条路径只会更慢 |
| `bw fast` 卡 60s 时甩 traceback | 捕 `TimeoutExpired` → `die(...,2)`；成败用 `json.loads` 判 | 子串 `'"ok": true'` 遇到紧凑 JSON 会误判 |
| 裸 `bw`（无子命令）+ 粘性拟人 → AttributeError | `parse_args` 后先 `hasattr(a,"f")` | 手滑敲 `bw` 不该是 traceback |
| 两进程同时记账 → `FileNotFoundError` / 后写者整批覆盖 | 临时文件名带 pid；五个写账函数加 `@with_lock`（`fcntl.flock`，可重入） | 换会话/并发定时任务时最先炸的就是这里 |
| `prune_state` 写成了 `keep.append(rec)` | 改 `keep_recs.append(rec)` | 面板里"还在、没关掉"的记录会被当场丢掉（2026-11-23 审计抓出） |
| `--keep-tabs` 跳过了 `human_set(False)` | 单独分支复位拟人并说明 | 拟人粘到下一次任务 |
| 复用判据用精确串、`close` 用前缀容错 | `go` 改用同一套 `_title_match` | 标题被截断时 `go` 多开一张、`close` 却认得 |
| 带 `#`/`;` 的 URL 走地址栏时改的是当前标签 | 先 `open_new_tab()` 再走地址栏 | 会顶掉用户正看的页 |
| `tabs close` 关掉后不清记账 | 成功后 `prune_state([...])` | 记录永久残留，后面每次 close 都为它失败 |
