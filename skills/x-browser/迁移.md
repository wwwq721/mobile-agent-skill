# 迁移.md · x-browser（`bw`）

> 给"下一个接手这个技能的人"看：**第一次把它装到一台新手机上**要注意什么，**以后改代码**要注意什么。
> 目的与命令清单见 [SKILL.md](SKILL.md)，实现细节见 [reference.md](reference.md)；这里只记"换机就废"和"改错会出事故"的部分。
> 本机（2026-11-21 实测）：Android 10 / MIUI / 1280×2772 / X 浏览器 `com.mmbox.xbrowser` / Sogou 输入法。

## 一、第一次部署（新机落地）

顺序不能反：**先要权限 → 再装盘 → 再逐项验收**。跳到装盘直接测，前面所有"打开失败"都会被误判成"页面空白"。

| 步 | 做什么 | 怎么判成功 | 踩过的坑 |
|---|---|---|---|
| 1 | 放行无障碍 | `android-a11y-cli service status` → `running:true` | 重新授权的当天，`state:ON` 也可能 `permissionHeld:false`，此时只剩状态栏节点、点按全废 |
| 2 | 确认"自己切回前台"这条路可用（`bring_minis_front()`：Recents → 点 Minis 卡片） | `front()` 变成 `com.openminis.app` 后，`bw go` 走 intent | 本机**没有**「后台弹出界面」这类开关（2026-11-22 核实），别去翻设置；Recents 里卡片标签形如 `Minis,未加锁`，按钮位置换机要重测；用户不想被打断时用 `BW_NO_FRONT=1` 退回地址栏路径 |
| 3 | 装软链 + 确认依赖 | `ln -sf /var/minis/skills/x-browser/bw /usr/local/bin/bw`；`bw -h` 有输出；另需 `android-a11y-cli`、`android-open`、`minis-browser-use`（`bw fast` 用）、`scr`（`bw shot` 用，来自 screen 技能） | 四个依赖都不在 `bw -h` 里：缺 `scr` 时 `bw shot` 才报错，缺 `minis-browser-use` 时 `bw fast` 才报错 |
| 4 | 体检 | `bw state` 打出《标题》+ 块数/字数 | 报"读不到浏览器界面 / 只看到状态栏节点"= 熄屏或没在前台，**不是**技能坏了 |
| 5 | 逐项验收 | 按 §五 的基线清单跑一遍，**耗时可不同，✔/✘ 必须对** | 抄旧机数值当期望值 → 把"慢"判成"坏"。`close` 要安全地验：先 `bw go --new <随便一个公开页>` 自己开一张，再 `bw close`，看 `before/after` 正好差 1——**别拿用户正开着的标签试** |
| 6 | 留基线 | 部署完先 `git add` 再改；`git log` 记下这次提交号 | 没提交就改，后面改坏了回不去 |

**新机第一件事是重测几何，不是改代码**：屏幕、地址栏、底栏、卡片边界、键盘回车键全都会变（§三 的表现在就是从 1080×2400 换到 1280×2772 得来的）。代码里已改成首帧实测 + 比例，常量写死也没用（`_measure()` 每帧都会覆盖 `W/H/TOP/BOTTOM`）。
重测方法（三行够了）：`ui dump` 看根节点 bounds → 屏幕；顶部宽条（宽>0.55W、高 90–190、top<0.25H）的 bottom → 地址栏下沿；包内可点节点里 top 最靠下者（>0.85H）→ 底栏上沿。卡片边界要进面板后按"带 × 的标题行"取 `left/right`。
新机仍然错位 → **改判据或加兜底，别改常量**。

## 二、后续修改注意事项

按"你要动哪块"查，每块都写清**必须连带做什么**。展开的证据在 §四对应小节。

| 要动 | 必须连带 | 否则会怎样 |
|---|---|---|
| 屏幕/几何（`_measure`、`addr_bar`、`tab_rows`） | 只用首帧实测值或比例，**不许写死坐标**；常量改了不生效（`_measure()` 每帧覆盖），要改就改判据；改完跑 `bw state` + `bw tabs verify` | 换机即废；本机曾因 `W,H=1080,2400` 丢掉正文 2255–2574 段 |
| `go` 的开页逻辑（含 `via_bar`） | 改完必须同时检查**记账**（`note_tab`/`rename_active`）、**失败清理**（`_bar_cleanup`）与**失败语义**（exit 3）；落地判据见 §4.7 | 曾经"没跳走"被报成成功，还把用户自己的页记成我开的 → `close` 会去关人家的页 |
| 记账（`shared/bw/session.json`，**跨会话共用**） | 一条标签一条记录；只在**确认落地**时写：新开走 `note_tab`，复用同一标签（地址栏跳转）走 **`rename_active` 就地改名**，不确定是否同一标签才 `retitle_active` 追加；`session_titles()` 还会把 `last` 算一条；`prune_state` 只在核对成功（`status ∈ ok/partial`）时动账 | 曾把 15 条记录删光，而标签还开着；复用不记账会让那张卡成为"关不掉的孤儿"，3 次后记录被丢弃 |
| `close` | 守住四条：只关自己开的、关一张的判据是"这个标题少一张"、数量护栏 `after = before - closed`、面板数到 0 张时判 `noview` 不许动账 | 2026-11-19 曾因"全屏卡片数少一张"连坐关掉用户 5 张卡 |
| 面板（`open_tabview`/`_cards`） | 进面板后**再确认一次** `in_tabview()`；卡片判据是三档：① `新建标签` 磁贴 + 标题行同一 y 带靠右 × 小图标 → ② 在带 × 的行里取出现最多的 `(left,right)`、并列取 left 更大 → ③ 按 top 间距 ≤240 截断 | 少了任一轮都会数错：只按几何会把网页正文当卡片；不收敛会把正文里挨着图标的行算进来 |
| 拟人（`human`） | 点击只能真实触摸；`tap xy` 两次不中报失败，**不许退回注入式 `tap node`** | 注入点击没有触摸事件，页面能识别；等于骗人 |
| 错误文案 | 报事实（前台是谁、看到几个节点），不猜病因；给一条可执行下一步 | 把熄屏/前台不对/真空壳混成"页面被裁" |
| 文档 | 改行为必须同步 SKILL.md 的命令行与默认值、reference.md 的几何、本页的约束；**三处不许互相矛盾** | 2026-11-21 发现 SKILL.md 还写着"close 回桌面"、reference.md 还写着旧机 `H-100` |

**改记账/`go` 不用真机也能先验**：`exec` 模块后替换 `bar_text`/`note_tab`/`retitle_active`/`_go_impl`，断言"新开→note_tab、复用→retitle_active"的分流；再跑 `python3 -m py_compile bw`。真机只留最后一步确认。

## 四、本机硬约束（不是 bug，改不掉；改代码前先对一遍）

### 4.1 有的动作只能用户手动点（MIUI + 后台启动限制）
- 现象：Minis 在后台时，`android-open` 可能返回 `Opened:` 而屏不动，或跳到 `com.miui.securitycenter`；表现是 `✘ 没打开：前台是 com.miui.home`。
- 现场话术：**"点一下 X 浏览器图标，再说一次"**；不要反复重试，也不要建议 `bw open`（命令不存在）。
- **别把"授权状态"当事实写进文档**：这是会变的环境状态，写死只会让下一个 agent 照着它去翻设置。文档只记"需要什么、怎么验、被拦时什么表现"。
- 本机实测：**没有**「后台弹出界面/允许后台启动」这类能给 Minis 开的开关（2026-11-22 核实），别建议用户去开。
- **能自己做**：`bring_minis_front()` 用 Recents 把 Minis 切回前台（`input key recents` → 点 `Minis,未加锁` 卡片），切回来后再发 intent 就被放行。代价是屏幕上会闪一下 Recents；`BW_NO_FRONT=1` 可禁用，退回"新建标签+地址栏"。
- 边界：这一关过了（能拉起浏览器）也**不代表** VIEW intent 送得到——那是另一条限制，见 §4.4。

### 4.2 熄屏读不到界面
熄屏后 `ui info` 只报 `com.android.systemui`（windowCount=1），`dump` 只有状态栏节点；也无法远程点亮。
已改为明确报：`✘ 没打开：读不到浏览器界面 / 只看到状态栏节点——屏幕可能锁着/熄了`。

### 4.3 地址栏未聚焦时读不到 URL
判"到底跳没跳"没有可靠字段，只能看正文或地址栏里已有的域名。所以判据用"键盘收起 + 标题非空"，不用"签名变了"（点开地址栏本身就会变，曾出现 460ms 假成功）。

### 4.4 VIEW intent 只在 Minis 在前台时能送达（后台启动被系统 cancel）
- **真因不是"浏览器在前台"**，而是"浏览器在前台 ⇒ Minis 在后台 ⇒ Android 10 直接 cancel 这次 `startActivity`"，且 `startActivity()` 不抛异常、`android-open` 照样回 `Opened:`。
  2026-11-22 矩阵实测：同一条 `intent:...VIEW;package=com.mmbox.xbrowser` 在 Minis 前台 **21ms 落地**并新开一张卡；把浏览器切到前台再发，页面一字节不动；**连公认能用的 `MAIN/LAUNCHER` 在 Minis 后台时也不动**。改 data/package/flags 都没用。
- 所以 `bw` 现在按前台分流：
  1. 新开页 + 浏览器在前台 → **先 `bring_minis_front()` 把自己切回前台**，再发 intent（实测 457ms）；切不回来或 `BW_NO_FRONT=1` → "新建标签 → 地址栏"（541ms，不闪屏）。
  2. 复用我的页 → 走地址栏（intent 会开新标签，不适合复用），约 4s。
  3. Minis 已在前台 → 直接 intent，约 0.5–0.7s。
- 其余两条仍然有效：① 页面没变且地址栏无目标域名 → `exit 3`，**不记账**；② 新建标签走地址栏 0.5–4s 落地，不顶掉用户当前页。
- 有用户页的场景已实测：面板 4 张卡 → `close` 只关我开的 1 张（`before=4 after=3`）；`before=2 after=1` 也复现过。

### 4.5 面板可滚动，只数得到一屏
`bw tabs verify` 与 `close` 的 `before/after` 只覆盖当前一屏；超出屏的卡片不在核对面里。

### 4.6 `open_tabview` 会假成功
出现过"报进了面板，但下一帧已被带回网页"：`before` 数成 0 → 判成"我的标签都不在了"→ 连删 15 条记录，而标签其实还开着。
防护两道：进面板后再确认一次 `in_tabview()`，否则 `noview`；`prune_state(inspected=False)` 时账本一个字不动。

### 4.7 地址栏提交要试三条路，且"落地"不能只看标题
- 三条路：键盘「开始」`H-186` → 地址栏右侧箭头（`0.9375W`, 地址栏中心 y）→ 键盘 `H-100`（旧机）。本机顶部地址栏打完字键盘有时自己收起，只剩箭头可点。
- **落地判据只能是"键盘收起 + 地址栏不再显示我刚打的字"**：`example.com` 与 `example.org` 标题都叫 `Example Domain`、正文 900 字一字不差，用"标题变了"会判失败，用"内容变了"也会判失败。
- 失败的地址栏输入会留下**联想浮层**（键盘已收起，但列表里有一行 `搜索:`）：不收拾，下次 `go` 会把浮层里那行字当成"地址栏已是目标域名"→ 假成功。所以失败后一律 `_bar_cleanup()`（按一次 back），并且域名判据要求 `not ime_up` + 正文 ≥80 字 + 非浮层。

### 4.8 面板刚打开时数不到卡片（`verify` 也会）
- 实测 `open_tabview()` 成功、`in_tabview()` 也真，但 `_cards()` 在动画中返回 0 张 → 旧逻辑据此判"我的标签都不在了"，把记录当成已关。
- 现在：等到 2.5s 仍为 0 → 退面板重开一次 → 再等 2.5s 仍为 0 → `noview`，账本一个字不动。
- `bw tabs verify` 同样要等（2026-11-22 实测：刚 `close` 完立刻 verify，会把 1 张卡报成 0 张）。
- 另有一条计数上限：**最后一张标签没有 ×**（浏览器不允许关最后一个），它不在"带 × 的卡"里；面板只剩它时 `_cards()` 为 0，`close` 会判 `noview`（安全），`verify` 的文案会说明这一点。

### 4.9 `bw find` 慢且脆（17–22s）
原因链：必应移动版结果块延迟渲染（落地只有 132 字搜索头 + 一张广告卡，6–8s 后才出条目），intent 有时还停在原页。
兜底：搜索页标题不匹配 → 走地址栏重开；解析不到 → 下滑最多 2 屏再解析。
要快就走 `bw go "https://cn.bing.com/search?q=..."` → `bw read` → `bw tap`，能省一半时间。

## 六、未验证 / 已知短板

1. ~~`bw fast` 未测~~ → 2026-11-22 实测：读完 8–10ms，**打开要等渲染**（1.8s / 3.4s / 重站点 30.7s）。"40–80ms"只指读完这一段，别当成"打开页面 40ms"。
2. `dismiss_dialog` 按文字点（取消/关闭/以后再说/不允许），不依赖坐标；**真机上还没遇到弹窗走过这条路径**（未验触发侧）。
3. `scroll to-text` 在 X 浏览器未测。
4. 拟人 `type --submit` 在百度页曾报"这一屏没有可写的输入框"（原因未定位）。
5. `key fwd` 未单测。
6. 面板滚动只数一屏（4.5），多于 6 张卡时 `verify` 只能给出下界。
7. 拟人输入是 `ACTION_SET_TEXT` 逐段重写，**没有 keydown**——靠 `isTrusted`/`keydown` 判人的站点仍能识别。

## 七、目的对照

| 目的原话 | 现在能做到 | 证据 | 差在哪 |
|---|---|---|---|
| 「快速高效的用」 | 单条命令都在秒级（数值见 §五，不在两处各抄一遍） | §五 | `find` 17–22s；`go` 在"浏览器已在前台"时要走新建标签+地址栏，比 intent 慢 2–3s |
| 「更拟人化」 | 真实触摸点击、随机滚动、地址栏分段输入、输入长度递增 | §五、§二"拟人"行 | 输入无 keydown，这是天花板，不承诺 |
| 「用完把没用的界面关闭」 | 只关自己开的；4 张卡时只关 1 张（`before=4 after=3`）；关不掉 exit 3 且保留记录 | §4.4、§4.5 | 面板只数一屏；连续 3 次关不掉才放弃 |

## 八、其余已修事项（只列 §二/§三/§四 没覆盖的；过程细节查 `git log`）

| 现象 | 修法 | 别改回去的理由 |
|---|---|---|
| 一次 `bw go` 挂死，shell 900s 超时、日志 0 字节 | `_open()` 给 `android-open` 统一 15s 超时 | 无超时会把整条命令链拖死，看不出卡在哪 |
| `bw state \| head` 抛 `BrokenPipeError` 堆栈 | `__main__` 兜 `BrokenPipeError` | 管道截断是正常用法，不该打堆栈 |
| `go` 一次回退要 19s | `via_intent(wait_ms=3500)`、`_bar_retry` 2→1 次 | 回退那条路径只会更慢，多试无收益 |
| 账本为空时 `close` 只剩一行耗时 | 开头也说一句并复位拟人 | 静默看着像没执行 |
| 账本原先放在 `workspace/bw/`（某会话私有）→ 另一个会话看不见这些标签，永远关不掉 | 改到 `/var/minis/shared/bw/session.json`，首次读取时自动搬旧账 | 标签属于浏览器而不是某个会话；换会话就得能接着关（2026-11-22 复查） |
| 复用我开的页后标题变了，却不记账 → 那张卡成了"关不掉的孤儿" | `go()` 拆成包装 + `_go_impl()`，成功出口统一记账：新开 `note_tab`、复用 `retitle_active` | 漏记的卡 `close` 认不出，3 次后记录被丢弃，标签永远留着（2026-11-21 复核发现） |
